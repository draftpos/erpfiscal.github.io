# Authentication & Security

All requests to the HavanoZimra Cloud API (except the initial token generation call) must be authenticated using **Frappe API Keys** along with a valid **CSRF Token**.

---

## Required Request Headers

Every call to endpoints such as `pingzimra` or `sendinvoice` must include the following headers:

```http
Authorization: token <API_KEY>:<API_SECRET>
X-Frappe-CSRF-Token: <CSRF_TOKEN>
Content-Type: application/x-www-form-urlencoded
```

### Header Descriptions

| Header | Description | Example |
| :--- | :--- | :--- |
| `Authorization` | Basic Frappe token authentication header formatted as `token key:secret`. | `token 9876543210abcde:1234567890fedcba` |
| `X-Frappe-CSRF-Token` | The CSRF verification token obtained from `/api/method/havanozimracloud.api.token`. | `a9f8e7c2f23d46a89c...` |
| `Content-Type` | Payload encoding. Standard form URL-encoded format is required for all POST endpoints. | `application/x-www-form-urlencoded` |

---

## CSRF Token Generation

The CSRF token is required by the backend to guard against cross-site request forgery and validate the session state.

### Endpoint

```http
POST /api/method/havanozimracloud.api.token
```
*(Also accessible via GET request depending on server configuration)*

### Example cURL Request

```bash
curl -X POST https://your-site-name/api/method/havanozimracloud.api.token
```

### Example Response

```json
{
  "token": "a9f8e7c2f23d46a89c0b1e4f5a6b7c8d9e0f"
}
```

> [!NOTE]
> Some server configurations may encapsulate the token inside a `message` key:
> ```json
> {
>   "message": "a9f8e7c2f23d46a89c0b1e4f5a6b7c8d9e0f"
> }
> ```
> Your client code should inspect both `token` and `message` properties when parsing the response.

## Session & Cookie Handling

When calling the API from platforms such as .NET (VB.NET, C#), Java, or Python, maintaining a `CookieContainer` or session is recommended:

```ini
Cookie: full_name=Guest; sid=Guest; system_user=no; user_id=Guest
```

In .NET (`HttpClientHandler` / `CookieContainer`):

```csharp
var cookieContainer = new CookieContainer();
var baseUri = new Uri("https://your-site-name");
cookieContainer.Add(baseUri, new Cookie("full_name", "Guest"));
cookieContainer.Add(baseUri, new Cookie("sid", "Guest"));
cookieContainer.Add(baseUri, new Cookie("system_user", "no"));
cookieContainer.Add(baseUri, new Cookie("user_id", "Guest"));
```

## Security Best Practices

1. **Keep Secrets Server-Side**: Never embed your `API_KEY` or `API_SECRET` in client-side code (e.g. mobile apps, browser JavaScript). Always route requests through your secure backend service.
2. **Use TLS 1.2 or TLS 1.3**: All traffic must occur over encrypted HTTPS connections. Ensure your application runtime enforces modern TLS protocols.
3. **Token Caching & Lifecycle**: Fetch a CSRF token at the start of your fiscalization batch or session and reuse it. If a request returns an authentication or CSRF expiration error, re-fetch the token and retry the operation once.
