# Receipt & QR Code Printing

Under ZIMRA regulations, every fiscal invoice issued to a customer (whether printed on 80mm thermal paper, A4 PDF, or emailed) must display specific fiscal identifiers, tax category summaries, and a scannable **ZIMRA Verification QR Code**.

---

## Required Fiscal Fields on Receipts

When a successful response (`ResponseCode: "0"`) is returned by `/api/method/havanozimracloud.api.sendinvoice`, extract and render the following fields on the final customer receipt:

| Field Name | Description | Placement on Receipt |
| :--- | :--- | :--- |
| **Taxpayer Name & Trade Name** | Registered entity name and trading name. | Top Header |
| **TIN & VAT Number** | Taxpayer Identification Number and VAT registration. | Top Header |
| **Device Serial Number** (`DeviceSN`) | The official fiscal device serial number. | Header / Fiscal Footer |
| **Invoice / Receipt Number** | Your internal invoice number (`invoice_number`). | Header |
| **ZIMRA Global Invoice No** (`GlobalInvoiceNo`) | The sequential fiscal receipt number assigned by ZIMRA. | Fiscal Footer (Bold) |
| **Fiscal Day Number** (`FiscalDay`) | Current operating fiscal day counter. | Fiscal Footer |
| **Tax Breakdown Table** | Subtotals grouped by tax band (`15% VAT`, `Zero-Rated`, `Exempt`). | Above Total |
| **ZIMRA Verification QR Code** | QR code encoding the `VerificationURL`. | Bottom of Receipt |

## QR Code Generation

The `VerificationURL` returned by the API points to the ZIMRA public verification portal:

```ini
https://efms.zimra.co.zw/verify/v1?device=1234567890&rec=100452&date=20261111...
```

### QR Code Parameters

- **Error Correction Level**: Medium (`Level M`) or High (`Level H`).
- **Encoding**: UTF-8 string encoding of `VerificationURL`.
- **Minimum Size**: Recommended minimum print dimension of $25\text{mm} \times 25\text{mm}$ (or at least $150 \times 150$ pixels) to ensure fast scanning by smartphones and handheld scanners.
