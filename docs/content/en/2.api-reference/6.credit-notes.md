# Credit Notes & Reversals

In Zimbabwean fiscal legislation, any sales return, invoice cancellation, or price downward adjustment must be submitted as a fiscal **Credit Note** linked to the original fiscal invoice.

Under HavanoZimra Cloud, credit notes use the same endpoint (`/api/method/havanozimracloud.api.sendinvoice`) by toggling the `invoice_flag` to `1` and providing reference identifiers.

---

## Required Parameters for Credit Notes

When `invoice_flag = 1`, the following three fields become **mandatory**:

| Parameter | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `invoice_flag` | `int` | **Yes** | Set to `1` to designate this transaction as a Credit Note. |
| `invoice_comment` | `string` | **Yes** | Reason for issuing the credit note (e.g. `"Damaged goods returned by customer"`). |
| `original_invoice_no` | `string` | **Yes** | The internal invoice number of the original sales invoice being adjusted (e.g. `INV00123`). |
| `global_invoice_no` | `int` / `string` | **Yes** | The official ZIMRA fiscal receipt number (`GlobalInvoiceNo`) returned by ZIMRA when the original invoice was fiscalized. |

---

## Example Request (Credit Note)

```bash
curl -X POST https://your-site-name/api/method/havanozimracloud.api.sendinvoice \
  -H "Authorization: token YOUR_API_KEY:YOUR_API_SECRET" \
  -H "X-Frappe-CSRF-Token: YOUR_CSRF_TOKEN" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "device_sn=1234567890" \
  -d "add_customer=0" \
  -d "invoice_flag=1" \
  -d "currency=USD" \
  -d "invoice_number=CN-2026-0001" \
  -d "customer_name=John Doe" \
  -d "trade_name=JD Traders" \
  -d "customer_vat_number=12345678" \
  -d "customer_address=123 Market Street" \
  -d "customer_telephone_number=+263771234567" \
  -d "customer_tin=87654321" \
  -d "customer_province=Harare" \
  -d "customer_street=Market Street" \
  -d "customer_houseNo=12" \
  -d "customer_city=Harare" \
  -d "customer_email=john@example.com" \
  -d "invoice_comment=Customer returned item due to wrong specification" \
  -d "original_invoice_no=INV00123" \
  -d "global_invoice_no=100452" \
  --data-urlencode 'items_xml=<ITEMS><ITEM><HH>1</HH><ITEMCODE>99001868</ITEMCODE><ITEMNAME>Milo 500g</ITEMNAME><ITEMNAME2>Milo</ITEMNAME2><QTY>1</QTY><PRICE>6.10</PRICE><TOTAL>6.10</TOTAL><VAT>0.80</VAT><VATR>0.15</VATR><VNAME>VAT</VNAME></ITEM></ITEMS>'
```

## Response Structure

A successful credit note returns a new `GlobalInvoiceNo` specifically for the credit note document:

```json
{
  "ResponseCode": "0",
  "ResponseMessage": "Credit note successfully processed",
  "DeviceSN": "1234567890",
  "InvoiceNumber": "CN-2026-0001",
  "GlobalInvoiceNo": "100453",
  "OriginalInvoiceNo": "INV00123",
  "OriginalGlobalInvoiceNo": "100452",
  "VerificationURL": "https://efms.zimra.co.zw/verify/..."
}
```

---

## Important Rules

1. **Unique Credit Note Number**: The `invoice_number` must be unique in your system (e.g., `CN-0001` or `REV-0001`). Do not reuse the original invoice number for `invoice_number`.
2. **Global Invoice Reference**: Always retrieve and persist the `GlobalInvoiceNo` when submitting an original invoice; it is required if a credit note or refund is ever issued against that invoice.
3. **Partial vs Full Credit Notes**: You can issue a credit note for fewer items or smaller quantities than the original invoice, provided the credited items and amounts do not exceed the original invoice values.
