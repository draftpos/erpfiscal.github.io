# Offline Invoicing & Buffering

In high-volume retail or industrial settings, sales must not be halted if the ZIMRA FDMS servers experience network latency, connectivity drops, or scheduled maintenance.

Under ZIMRA regulations, registered operators are permitted to operate in **offline mode** for a designated grace period, provided all transactions are locally logged in strict sequential order and transmitted as soon as network communication is restored.

---

## Endpoint Details

The offline invoice endpoint accepts identical parameters to the primary [`sendinvoice`](/en/api-reference/send-invoice) endpoint:

- **Method**: `POST`
- **Path**: `/api/method/havanozimracloud.api.sendinvoice` *(or designated offline route)*
- **Authentication**: Required (`Authorization` + `X-Frappe-CSRF-Token`)
- **Content-Type**: `application/x-www-form-urlencoded`

---

## Recommended Architecture Pattern

To guarantee zero transaction loss, implement a local queue pattern in your ERP or POS application:

```
[POS / Billing Terminal]
       |
       v
[Attempt Real-time sendinvoice]
       |
  +----+------------------+
  | Success (Response 0)  | Failure / Timeout / Ping Failed
  v                       v
[Print Fiscal Receipt]  [Store Invoice in Local Offline Queue DB]
                        [Print with Offline Receipt Marker]
                                  |
                        [Background Sync Service]
                                  |
                                  v
                        [Sync to HavanoZimra Cloud when Online]
```

---

## Best Practices for Offline Mode

1. **Ping Before Batch**: Use [`pingzimra`](/en/api-reference/ping-zimra) to periodically verify connection health. If ping fails, mark the gateway status as *Offline* and queue upcoming invoices locally.
2. **Strict Chronological Order**: When flushing the offline queue back to HavanoZimra Cloud, submit transactions in the exact order in which they were created (`created_at` timestamp).
3. **Persist Payload & State**: Save the exact form parameters (including `items_xml`) in your local offline table. Do not alter prices or line items between offline creation and sync.
4. **Offline Identification**: Flag offline receipts in your POS records so staff can audit pending versus completed fiscalizations.
