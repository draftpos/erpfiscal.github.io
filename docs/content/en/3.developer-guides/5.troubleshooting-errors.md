# Troubleshooting & Error Reference

This guide covers common error scenarios, status codes, and resolution steps when working with HavanoZimra Cloud API.

---

## Error Resolution Matrix

### 1. Invoice Number Already Exists

```json
{
  "ResponseCode": "1",
  "ResponseMessage": "Invoice Number Already exist for this User, Please change invoice number format: INV00123 cannot be used"
}
```

- **Root Cause**: ZIMRA requires every fiscal invoice to possess a strictly unique document number within your taxpayer account. The provided `invoice_number` has already been submitted and fiscalized.
- **Solution**:
  - Check your ERP database to confirm if `INV00123` was already successfully fiscalized and retrieve its existing `GlobalInvoiceNo`.
  - If re-issuing a new document, generate a unique incremental invoice number (e.g. `INV00124` or append a timestamp/suffix).

---

### 2. Device Account Not Found or Disabled

```json
{
  "ResponseCode": "1",
  "ResponseMessage": "Zimra User Account not found for Device SN: 1234567890 or Account disabled"
}
```

- **Root Cause**: The `device_sn` sent in the request does not correspond to an active, assigned device in your HavanoZimra Cloud account.
- **Solution**:
  - Verify that `device_sn` is correctly typed without leading or trailing spaces.
  - Check your cloud dashboard or contact your Havano administrator to verify that the device is activated and mapped to your company profile.

---

### 3. Missing Required Parameters

```json
{
  "success": false,
  "message": "Missing required parameters: 'Device serial number'"
}
```

- **Root Cause**: A required POST parameter was omitted from the form body or sent with an empty key name.
- **Solution**:
  - Verify that your request header includes `Content-Type: application/x-www-form-urlencoded`.
  - Confirm that all mandatory parameters (`device_sn`, `currency`, `invoice_number`, `customer_name`, `items_xml`, etc.) are present in the form body.

---

### 4. CSRF Validation Failure (HTTP 403)

```json
{
  "exc_type": "CSRFTokenError",
  "message": "CSRF Token missing or incorrect."
}
```

- **Root Cause**: The `X-Frappe-CSRF-Token` header was omitted, expired, or does not match the session cookies.
- **Solution**:
  - Invoke `/api/method/havanozimracloud.api.token` to get a fresh token.
  - Ensure the token is passed in the `X-Frappe-CSRF-Token` header on every subsequent request.
  - When using .NET or Python, make sure cookies are preserved using `CookieContainer` or `requests.Session`.

---

### 5. XML Formatting & Calculation Errors

- **Root Cause**: Missing tags in `items_xml` or arithmetic inconsistencies between line items and totals.
- **Solution**:
  - Ensure all 10 tags (`<HH>`, `<ITEMCODE>`, `<ITEMNAME>`, `<ITEMNAME2>`, `<QTY>`, `<PRICE>`, `<TOTAL>`, `<VAT>`, `<VATR>`, `<VNAME>`) exist in every `<ITEM>` element.
  - Verify that $\text{TOTAL} = \text{QTY} \times \text{PRICE}$.
  - Verify that `<VAT>` equals the calculated VAT portion according to the `<VATR>` rate.
  - Check for unescaped characters such as `&`, `<`, `>` in item names.

---

### 6. ZIMRA FDMS Host Unreachable or Timeout

- **Root Cause**: Network latency or temporary maintenance on ZIMRA government servers.
- **Solution**:
  - Run [`pingzimra`](/en/api-reference/ping-zimra) to test connectivity.
  - If unreachable, transition your POS / ERP to [Offline Invoicing](/en/api-reference/offline-invoicing), store the transaction in your local queue, and retry submission once connectivity returns.
